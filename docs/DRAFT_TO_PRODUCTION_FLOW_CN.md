# PlayZPD 从草稿到生产的受控流程

## 阶段一：私人草稿

- 所有未批准内容先放在 `PlayZPD-Drafts`。
- 草稿可以包含构想、文案、页面结构和实验方案。
- 草稿不得自动复制、推送或发布到 `playzpd-site`。
- 草稿不得包含不必要的儿童、学生或家庭个人信息。

## 阶段二：Ray 批准范围

Ray 在进入生产仓库前确认：

- 要解决的问题和目标页面。
- 允许修改的文件。
- 不允许修改的内容。
- 是否涉及支付、隐私、Analytics、SEO、Vercel 或 DNS。
- 完成标准和审核重点。

## 阶段三：生产分支准备

1. 更新本地 `main`，确认与 `origin/main` 一致。
2. 从最新 `main` 创建新分支。
3. 只复制或实现 Ray 已批准的内容。
4. 不修改范围外的生产文件。
5. 完成秘密、隐私、链接和差异检查。

## 阶段四：预览审核

- 只推送工作分支，不推送 `main`。
- 等待 Vercel Preview 生成。
- Ray 检查桌面端和移动端。
- Ray 检查品牌、链接、SEO、隐私和业务陈述。
- 预览未经 Ray 明确批准不得合并。

## 阶段五：人工合并

- Codex 不自动合并。
- Ray 在 PR 中明确批准后才可合并。
- 支付、隐私、Analytics、canonical、Vercel 和 DNS 变更需要额外确认。
- 合并后记录生产版本和回滚提交。

## 核心流程

`PlayZPD-Drafts 私人草稿 -> Ray 批准 -> 生产分支 -> Vercel Preview -> Ray 审核 -> PR 人工合并`
