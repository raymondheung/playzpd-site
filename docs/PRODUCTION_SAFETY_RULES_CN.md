# PlayZPD 生产安全规则

## 不可绕过的规则

- 不得直接修改或推送 `main`。
- 不得自动合并、自动发布草稿或自动部署生产。
- 不得使用 `git push --force`。
- 不得提交 API 密钥、访问令牌、密码、私钥、环境变量或其他秘密。
- 不得在代码、截图、日志、提交信息或 PR 中公开秘密。
- 不得发布儿童、学生或家庭的姓名、联系方式、学校、位置、照片、账号或其他可识别信息。
- 范围不清楚时必须停止并询问 Ray。

## 高风险变更

以下内容必须获得 Ray 的单独明确批准：

- 支付、价格、Stripe、Whop、结账和退款流程。
- 隐私政策、表单、邮件收集、Cookie 和用户数据处理。
- Google Analytics、Vercel Analytics 或其他追踪工具。
- canonical 域名、robots、sitemap 和搜索验证。
- Vercel 项目设置、环境变量、生产域名和部署配置。
- DNS、域名注册商、重定向和证书设置。

## 每次提交前检查

1. 确认当前分支不是 `main`。
2. 运行 `git status` 并检查全部变更。
3. 搜索 `API_KEY`、`SECRET`、`TOKEN`、`.env`、私钥和凭证模式。
4. 确认没有儿童或学生个人信息。
5. 确认变更只包含批准范围内的文件。
6. 确认首页和其他生产内容没有意外变化。
7. 查看完整 diff，确认没有二进制文件或无关文件。
8. 提交后只推送当前分支。

## 生产保护原则

- `main` 应始终保持可发布和可回滚。
- 一个分支只处理一个明确目的。
- 小提交优于混合多个主题的大提交。
- Vercel Preview 是合并前的必要审核步骤。
- PR 必须说明变更范围、检查结果、风险和回滚方法。
