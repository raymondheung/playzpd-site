# PlayZPD 网站回滚指南

## 适用情况

- 生产页面显示异常。
- 链接、布局、SEO 或表单出现回归。
- 发布了错误内容或未经批准的内容。
- 发现隐私、安全或个人信息风险。
- 新版本影响支付、Analytics、canonical 或域名行为。

## 优先原则

- 先停止后续合并和发布。
- 保存错误页面、时间、提交 SHA 和影响范围。
- 不使用 `git push --force`。
- 不重写 `main` 历史。
- 优先使用 GitHub PR 的 revert 或新的回滚提交。

## 标准回滚步骤

1. Ray 确认需要回滚的生产提交或 PR。
2. 从最新 `main` 创建独立回滚分支。
3. 使用 `git revert <commit-sha>` 创建反向提交。
4. 检查 diff，确认只撤销目标变更。
5. 推送回滚分支并生成 Vercel Preview。
6. Ray 审核预览并明确批准。
7. 通过 PR 合并回滚，不直接推送 `main`。
8. 验证三个公开域名和关键页面。
9. 记录原因、影响、恢复时间和后续预防措施。

## 紧急隐私或安全事件

- 立即停止公开传播和后续变更。
- 不在公开 issue、日志或聊天中粘贴秘密或个人信息。
- 通知 Ray，并说明涉及的文件和提交，不复述敏感值。
- 仅删除代码中的秘密通常不够，相关凭证还必须在服务端撤销和轮换。
- DNS、Vercel、支付或账号级操作必须由 Ray 明确批准。

## 回滚后检查

- `main` 历史保持完整。
- 生产首页恢复预期版本。
- Vercel 部署状态正常。
- `playzpd.com`、`www.playzpd.com` 和默认 Vercel 域名行为已核对。
- 秘密、隐私和儿童信息风险已消除。
- 后续修复继续通过新分支、Preview 和人工批准。
